# Screenshot Backpressure

### Giving a coding agent eyes, so a reference photo can push back on the code it writes

When you ask a coding agent to write *visual* code — SVG, CSS, a `<canvas>` sketch,
a generative shape — it is essentially working blindfolded. It emits a plausible
blob of path data, you render it, and half the time it looks nothing like what was
asked. The agent never sees the gap, so it never closes it.

**Screenshot backpressure** is a tiny workflow that fixes this: after every edit the
code is rendered, screenshotted, and the image is handed *back* to the agent's vision.
A target reference photo sits next to it. The picture exerts pressure on the next
edit — the agent can finally see that the fern's koru are too big, that the trunk
doesn't meet the leaves, that the outermost fronds are poking out as bare spikes —
and corrects course. The loop runs until the render matches the goal.

The name borrows from streaming systems, where **backpressure** is the downstream
consumer pushing back on a too-eager producer to keep it in sync with reality. Here
the "downstream reality" is the rendered pixels, and the "producer" is the agent
generating geometry. Each screenshot is one unit of backpressure throttling the
hallucination.

## The example: cutting a ponga from code

The system was built while making a set of New Zealand–bush **paper-cut silhouettes**
for a website — each plant a single, deterministic SVG shape generated by a function
in a small library (`stamps.js`). The ponga (silver tree fern) is a good case study.

The target is a photo dropped in a `goal/` folder:

![A real ponga / silver tree fern](img/ponga-reference.jpg)

Dug out of git history, the code's idea of a silver fern started **rough** and was
walked to a clean paper-cut purely by looking at each render next to that photo:

| v0 — earliest | v1 — fishbone | v2 — tangled koru | v3 — final |
|---|---|---|---|
| ![lopsided sparse spiky fan on a stick](img/ponga-00-oldest.png) | ![spindly asymmetric fishbone tree fern](img/ponga-01-fishbone.png) | ![bushy ball with oversized tangled coils](img/ponga-early.png) | ![clean weeping crown, tight koru, square trunk](img/ponga-final.png) |
| a stick with a one-sided spray of spiky fronds | thin, scraggly, lopsided crown — no real form | a vase crown, but a black blob with huge tangled koru | weeping crown, tight inward koru, thick squared trunk |

Every change between those frames was driven by *looking*. A representative slice of the
feedback → parameter loop:

- *"the leaves overlapping are too black"* → fewer fronds, barer frond bases.
- *"the koru are sticking out the bottom of the leaves"* → root the fiddleheads at
  the crown hub, the same origin as the fronds.
- *"the koru radius needs to be smaller and face inward"* → tighten the spiral, flip
  the coil direction.
- *"the trunk should cleanly meet the origin of the leaves"* → a converging shoulder
  at the trunk top plus a solid hub.
- *"move the 2 back leaves to the front"* → skip the central upright fronds, draw two
  draping forward over the trunk.

None of these are things the agent could have known were wrong without seeing the
output. The reference photo and the rendered screenshot together turn vague art
direction into concrete, verifiable edits.

## How the loop works

```
  ┌─────────────────────────────────────────────────────────┐
  │  goal/ponga.jpg  (the target reference image)            │
  └─────────────────────────────────────────────────────────┘
                              │  compare
                              ▼
   edit stamps.js  ──►  render in isolation  ──►  screenshot  ──►  agent VIEWS png
        ▲                (stamp.html?name=ponga)   (Playwright)         │
        │                                                               │
        └───────────────  critique vs. goal + human note  ◄────────────┘
```

1. **A reference image** is the spec. A real photo (or a sketch) goes in `goal/`.
   It is worth a thousand words of prompt and removes most ambiguity about "what
   does good look like".

2. **Isolation harness.** Each shape is rendered alone, large, on a neutral panel —
   `stamp.html?name=ponga` for one stamp, `catalogue.html` for the whole set. Judging
   a shape in isolation is far easier than hunting for it inside a busy scene.

3. **Deterministic generation.** Every stamp is a pure function seeded by an integer
   PRNG, so a given seed always draws the *same* plant. The screenshot is therefore a
   faithful, repeatable readout of the code — no flaky randomness between loops.

4. **Screenshot harness.** A small Playwright script (`shoot.mjs`) loads the page,
   waits for paint, and writes a PNG (configurable viewports / scroll / zoom). One
   command, one image.

5. **The agent looks.** The PNG is read straight back into the agent's vision. It
   compares against the goal, narrates the residual problems, and makes the next edit.
   The human stays at the *art-direction* altitude ("tighter koru", "bushier, droopier")
   and lets the agent translate that into parameters and verify it.

The whole catalogue was refined this way — a dozen plants and birds, each looped to a
clean paper-cut:

## Why it works

- **Closes the perception gap.** LLMs write code confidently but cannot see pixels
  unless you show them. The screenshot is the missing sense.
- **Grounded in a target.** Comparing against a concrete reference image keeps the
  critique honest and convergent instead of drifting on vibes.
- **Tight, cheap iterations.** Render-and-shoot is seconds. Many small, *verified*
  steps beat one big unverified guess.
- **Right division of labour.** The human supplies taste and intent; the agent
  supplies the tedious parameter search and does its own QA by looking.
- **Determinism makes it trustworthy.** Seeded output means a screenshot is evidence,
  not a coincidence.

## The pieces

| Piece | Role |
|---|---|
| `goal/*.jpg` | reference images — the visual spec |
| `stamps.js` | deterministic, seeded shape library (the code under test) |
| `stamp.html` / `catalogue.html` | isolation harnesses to render one / all shapes |
| `shoot.mjs` (Playwright) | the screenshot tool — code → PNG |
| the agent | edits, renders, **looks**, critiques against the goal, repeats |

Give the agent eyes and a target, and let the picture push back.
